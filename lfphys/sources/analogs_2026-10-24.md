# lfphys: analogs and adjacent tools — 2026-10-24

Purpose: place `lfphys` among existing physics libraries, simulators and educational tools, on (1) technique
(language, numerics, precision/verification, GPU, architecture), (2) what a researcher gets (scope,
extensibility, interactive visualization, modified-physics / what-if, interpretations), (3) licence, cost, openness.

Rules: every statement about a third-party tool is taken from the tool's own site, repository or documentation;
the source keys in the per-tool notes resolve in §4. Anything not confirmed there is marked **not verified**. Access date
for all URLs: 2026-10-24.

## 0. lfphys as compared here (from its own README.md, LAYERS.md and source tree, 2026-10-24)

* Python ≥ 3.11; numpy, scipy, mpmath; python-flint 0.9.0 (Arb ball arithmetic) for certified references. CPU only,
  float64. About 8.3k lines of Python (package + tests); 139 test functions when this report was started, 349 test
  cases after the review fixes of 2026-10-24.
* Scope: SR kinematics and causality; Schwarzschild null/timelike geodesics, equatorial Kerr (Bardeen closed
  forms); scalar diffraction (Rayleigh–Sommerfeld, angular spectrum), Fresnel/Abelès multilayers, thin films;
  1-D Schrödinger (split operator, transfer matrices), radial bound states, hydrogen (Schrödinger + Dirac),
  Compton/Klein–Nishina, qubits and Bell correlations; QCD α_s to 4 loops, SU(3) factors; Cornell quarkonium.
* Architecture: `core` (accepted physics, each function tested against a closed form or a second method; sources
  named) / `theories` (approx, interpretations, models, alternatives; each must declare a conflict) / `laws`
  (law sets per world, flagged "modified physics" when they differ from accepted physics) / `tools` (statistics).
  Each module carries an `ABOUT` passport; `registry` builds the catalogue; `tests/test_layers.py` enforces the
  layering (core imports no theory; each theory names a conflict).
* Visualization: not in the library. Seven browser worlds (v01–v07) are thin wrappers served by one Python server
  in Docker; the player shows the modules a world uses with their layer.
* Licence: none declared (no LICENSE file, no licence field in pyproject.toml); private repository. Not packaged
  on PyPI.

## 2. Per-group notes (facts with sources)

### 2.1 Quantum

* **QuTiP** — Python (NumPy/SciPy/Cython backends); "open-source software for simulating the dynamics of closed and
  open quantum systems"; BSD-3-Clause. Version 5.3.1, 2026-08-04 (qutip.org, PyPI). Master equation, Monte Carlo,
  HEOM, steady states, Bloch-sphere plotting, quasi-probability plots via Matplotlib (user-guide chapter list).
  GPU only through family packages: qutip-jax ("pre-alpha", "not ready for use yet") and QuTiP cuQuantum
  ("experimental"). No interpretation layer, no what-if laws. Scope (open systems, many-level dynamics) is far wider
  than lfphys's qubits/1-D Schrödinger. Sources: [Q1][Q2][Q3][Q4].
* **qmsolve** — Python, BSD-3-Clause; eigenstates in 1-D/2-D/3-D (ARPACK `eigsh`, LOBPCG), time evolution by split-step
  Fourier and Cayley–Crank–Nicolson; GPU through CuPy (`split-step-cupy`, `crank-nicolson-cupy`, `lobpcg-cupy`);
  interactive Matplotlib sliders, Mayavi 3-D. Last PyPI release 2.0.0, 2021-09-27. Closest technical analog of
  `core.quantum.schrodinger1d`/`radial`, and wider (2-D/3-D, two particles, GPU), but no stated error control, no
  transfer-matrix reference, no interpretation readings. Sources: [Q5], PyPI JSON [P1].
* **Qiskit / Qiskit Aer** — Qiskit: Python API with a Rust core and a C API, Apache-2.0, version 2.6.1 (2026-10-22).
  Aer: statevector / density-matrix / unitary simulators with noise models; GPU via `qiskit-aer-gpu` (CUDA, x86_64
  Linux only); Aer is in "Reduced Maintenance Mode". IBM's CHSH tutorial runs the test on real hardware (example
  output: 63 of 64 parallel Bell pairs violate CHSH, mean witness 2.75); IBM Open Plan gives up to 10 min QPU per
  month free, pay-as-you-go from 96 USD/min. Relevant to lfphys v07 (Bell): Qiskit gives real-device data and noise
  models; lfphys gives the space-time side (causality of settings, light cones) and local-hidden-variable
  alternatives as declared theories. Sources: [Q6][Q7][Q8][Q9].
* **Quantum Composer** (Aarhus/Quatomic) — node-based ("flow-based") 1-D Schrödinger and Gross–Pitaevskii simulator
  on the C++ QEngine; "currently available as a free download"; licence not stated; supported OS list ends at
  macOS 10.13 / Ubuntu 16.04 (page appears unmaintained). Source: [Q10].
* **QuVis** (St Andrews) — 49 HTML5 + 68 Flash teaching simulations; CC-BY-NC-SA; topics include single-photon
  experiments, entanglement, "Hidden Variables", "Quantum Eraser", "Delayed Choice". Fixed simulations, no library,
  no stated numerical verification. Source: [Q11].
* **Quantum Game (Quantum Flytrap)** — browser puzzle game on photons, superposition, entanglement; the current page
  states no licence; source linked only for the 2014–2016 version. Source: [Q12].
* **Interpretation layers.** Searches for software that runs one quantum prediction under Copenhagen, de Broglie–Bohm
  and Everett side by side found none. Bohmian trajectories exist as single demos (e.g. Wolfram Demonstrations
  "Triple-Slit Experiment in the Causal Interpretation") and as paper code; no maintained library with an
  interpretation layer was found. This is a negative search result, **not proof of absence**. Sources: [Q13].

### 2.2 General and special relativity

* **EinsteinPy** — pure Python (NumPy, SciPy, SymPy, Astropy, Numba, Matplotlib/Plotly); MIT. "calculate and visualize
  geodesics, metric singularities and hypersurface embeddings in certain spacetimes"; symbolic tensors (Christoffel,
  Riemann, Ricci, stress–energy). Version 0.5.0 on PyPI, 2026-10-21. GPU: not mentioned. Interactive plots via
  Plotly (static web output, not a live simulation). Tests against analytic results: **not verified** (docs site
  unreachable on 2026-10-24). Wider than lfphys in symbolic GR; lfphys is narrower but uses closed forms
  (elliptic K for periapsis advance, Bardeen ISCO) with Arb references. Sources: [G1], PyPI JSON [P1].
* **KerrGeoPy** (Black Hole Perturbation Toolkit) — Python port of the Mathematica KerrGeodesics package; MIT;
  stable bound orbits (Fujita–Hikida analytic solutions), plunging orbits (Dyson–van de Meent), constants of
  motion, Mino and Boyer–Lindquist frequencies; not supported: polar, marginally bound, extremal Kerr. Last PyPI
  release 0.9.3, 2024-05-29. Covers generic (inclined, eccentric) Kerr orbits, which lfphys does not (equatorial
  only). Precision statements and comparison with the Mathematica package: **not verified**. Sources: [G2], [P1].
* **GYOTO** (Observatoire de Paris) — C++ library with Yorick plug-in and Python 3 extension; GPL-3.0; ray tracing
  and orbits in Kerr and in numerically computed 3+1 metrics; custom metrics and objects as C++ plug-ins
  (hence non-Kerr / what-if spacetimes are possible); MPI (`--nprocesses`) and POSIX threads (`--nthreads`)
  (Debian man page). GPU: not mentioned. Project site was unreachable on 2026-10-24. Sources: [G3][G4][G5].
* **OpenRelativity** (MIT Game Lab) — Unity toolkit, spin-off of the game *A Slower Speed of Light*; MIT licence;
  Lorentz contraction in a vertex shader, relativistic Doppler in a fragment shader (GPU), time dilation, adjustable
  speed of light (a what-if parameter); no GR; lighting and shadows "not supported at this time". Visual realism
  of SR on the GPU, but no numerical verification and no API for physics outside the renderer. Source: [G6].

### 2.3 QCD running coupling

* **RunDec / CRunDec v3** (Herren, Steinhauser) — Mathematica and C++; "five-loop corrections of the QCD beta
  function and four-loop decoupling effects"; heavy-quark mass scheme conversions; distributed with the CPC paper,
  Mendeley Data licence GPLv3. lfphys `core.qcd.running` stops at 4 loops with 3-loop decoupling (leading-order matching until the
  processing of the engine review on 2026-10-24), so CRunDec is
  strictly more complete and the natural independent reference for testing lfphys. Sources: [C1][C2].
* **rundec (Python)** — SWIG wrapper of CRunDec 3.1 by D. Straub; MIT (wrapper); binary wheels; PyPI 0.7,
  2025-11-18. Source: [C3], [P1].
* **REvolver** (Hoang, Lepenik, Mateu) — C++ library for RG evolution and automatic flavour matching of α_s and
  quark masses, including MSR masses and complex scales; Mathematica and Python (SWIG) interfaces; GPLv3 or later
  (program summary). Sources: [C4][C5].
* No tool found that pairs α_s running with a quarkonium potential model in an interactive view (lfphys v06);
  **not verified** as absent.

### 2.4 Optics

* **Meep** (MIT NanoComp) — FDTD Maxwell solver; Python, Scheme and C++ APIs; GPL-2.0; MPI distributed memory;
  dispersive ε(ω), μ(ω) with loss/gain, nonlinear, anisotropic media; adjoint solver for inverse design. FAQ: "No.
  Currently, Meep does not support GPUs via frameworks such as CUDA, OpenCL"; convergence is checked by doubling the
  resolution (user's job). Full-vector 3-D Maxwell — a different class from lfphys's scalar 2-D diffraction and
  1-D multilayers; no single-photon or interpretation layer. Sources: [O1][O2].
* **Ansys Lumerical FDTD** (commercial) — 3-D FDTD on GPU since release 2023 R2, single/multi-GPU, CUDA 12;
  meshing and scripts stay on CPU; GPU use tied to licence tier. Taken from the vendor help-center search snippets;
  the page itself returned HTTP 403 — **not verified** beyond the snippet. Price not public (**not verified**).
  Source: [O3].
* **tmm** (S. Byrnes) — Python/NumPy transfer-matrix method for multilayer thin films; MIT; absorption at any depth,
  ellipsometric parameters, film colour (with colorpy); a `tests.py` but no accuracy claims; derivations in
  arXiv:1603.02720. PyPI 0.2.0, 2024-11-26. Direct analog of `core.optics.interfaces`/`thin_films`; tmm is the more
  standard and broader (it also handles thick, incoherent layers: "combinations of thin and thick films", PyPI
  description); lfphys adds the Airy-sum
  cross-check, frustrated TIR and absorption as Joule heat, and single-photon readings in v05. Sources: [O4], [P1].
* **OpenFilters** (Polytechnique Montréal) — interference-filter design (needle, step, Fourier methods, rugates);
  GPL according to search results that quote the project page; **not verified** on the project site (page empty
  on fetch). Source: [O5].
* **LightPipes for Python** — scalar Fourier optics toolbox (apertures, lenses, beam splitters, free-space
  propagation incl. Fresnel); pure Python since 2.0.0 (NumPy, SciPy, pyFFTW); BSD-3-Clause; PyPI 2.1.5, 2024-08-05;
  GPU not mentioned. Analog of lfphys `core.optics.angular_spectrum` + `theories.approx.paraxial`, wider in optical
  elements, without stated error bounds. Sources: [O6], [P1].
* **diffractsim** — Python scalar diffraction (angular spectrum), polychromatic with CIE colour rendering, lenses,
  holograms; GPU through CuPy or JAX (`set_backend("CUDA")`), JAX also gives differentiable propagation; licence
  MPL 2.0 per PyPI metadata; no validation against analytic results on the page. Visual output closest to lfphys v02
  (coloured patterns), but no single-photon statistics or which-path physics. Sources: [O7], [P1].

### 2.6 General multiphysics, CAS, constants

* **COMSOL Multiphysics** — commercial FEM platform with physics modules (AC/DC, RF, Ray Optics, Semiconductor,
  Acoustics, Plasma, Particle Tracing, …; no quantum module in the product list). GPU (release months from COMSOL press-release search snippets): 6.3 (Nov 2024) added GPU

* **Wolfram Mathematica / Wolfram Language** — proprietary CAS; arbitrary-precision and interval arithmetic

* **Wolfram System Modeler** — Modelica/FMI multidomain modelling (version 15), 30-day trial, prices not shown.

* **SymPy physics** — BSD; submodules: vector, mechanics, biomechanics, control, optics, units, continuum

### 2.7 Certified / validated numerics (does anyone ship certified physics references?)

* **Arb (now part of FLINT 3) / python-flint** — ball arithmetic ("rigorous error tracking"); python-flint MIT,
  FLINT/Arb LGPL; python-flint 0.9.0, 2026-07-03. This is what lfphys uses. Arblib.jl (MIT) wraps Arb for Julia.
  Sources: [V1][V2].
* **mpmath `iv` context** — interval arithmetic, labelled experimental; "many functions do not yet properly support
  intervals". Source: [V3].
* **IntervalArithmetic.jl** — Julia, MIT, "compliant with the IEEE 1788-2015 standard". Source: [V4].
* **CAPD** (Kraków) — C++ library, GNU GPL: interval arithmetic, rigorous ODE solvers with derivatives, rigorous
  Poincaré maps, differential inclusions; used for computer-assisted proofs in dynamics (papers found by search). Source: [V5].
* **Mathematica** `Interval` / `CenteredInterval` — see 2.6.
* **DLMF Tables** (NIST + Univ. Antwerp) — on-demand tables of special functions with error certification; site
  refused connection on 2026-10-24; status taken from conference abstracts found by search (**not verified**).
  Source: [V6].
* **SciPy** tests `scipy.special` against mpmath (`scipy/special/tests/test_mpmath.py`): high-precision but not
  certified references. Source: [V7].
* **Finding.** General validated-numerics libraries exist (Arb, CAPD, IntervalArithmetic.jl, Mathematica). No
  physics library was found that ships certified references for its own physical quantities (periapsis advance,
  light deflection, Kerr ISCO, Dirac levels, barrier transmission) and tests its float64 code against them, as
  lfphys `core.certified` does. Negative search result; **not proof of absence**.

### 2.8 Modified-physics ("what if") precedents

* Domain tools that change one law on purpose exist: OpenRelativity (speed of light as a parameter), GYOTO (custom
  metric plug-ins), Universe Sandbox (free change of bodies under Newtonian gravity), cosmology codes with modified
  gravity — PySCo ("Cosmological N-body code with modified gravity theories", MIT, Python) and hi_class ("Horndeski
  and related scalar-tensor models", built on CLASS v3.4.0, licence not stated on the page). Sources: [G3][G6][E14]
  [W1][W2].
* None of them keeps refuted theories (ether, emission theory, corpuscular light, local hidden variables) as
  first-class modules next to accepted physics, nor flags a configured world as "modified physics". Negative search
  result; **not proof of absence**.

## 3. What is genuinely unique to lfphys, and where it is clearly weaker

### 3.1 Unique (no counterpart found in this search)

Status tags as required by `../../AGENTS.md` §3 rule 11: each item here is [useful] for lfphys's positioning; all are negative
search results, not proof of absence.

1. **Accepted vs alternative physics as an enforced architecture.** Layers core / approx / interpretations / models /
   alternatives, an `ABOUT` passport per module with `validity`, `basis` and `conflicts`, and tests that enforce the
   rules (core imports no theory; every theory names a conflict). Astropy's per-constant provenance is the nearest
   precedent, and it covers constants, not laws.
2. **Interpretations as code with a no-new-prediction test.** Copenhagen, de Broglie–Bohm and Everett readings of
   the same ψ, with the rule that an interpretation must reproduce the core's outcome statistics (tested: Bohmian
   positions distributed as |ψ|²). Elsewhere Bohmian trajectories appear only as single demos or paper code.
3. **Certified references for physical quantities as test oracles.** Arb enclosures for periapsis advance, light
   deflection, Kerr ISCO, Hankel functions, Fresnel integrals, Dirac levels, Klein–Nishina, barrier transmission,
   used to test the float64 code; one real defect found (Hankel asymptotics at x = 1e8). Validated-numerics
   libraries (Arb, CAPD, IntervalArithmetic.jl, Mathematica `CenteredInterval`) provide the means; no physics
   library was found that ships such references for its own outputs.
4. **Refuted and what-if theories with their experimental bounds** (ether, Ritz, Soldner corpuscular light,
   Brans–Dicke bounded by Cassini, GRW, P ∝ |ψ|^p, local hidden variables |S| ≤ 2) in one library, combined by law
   sets per world.
5. **Cross-domain breadth in one small, uniform API** (SR, GR, wave and ray optics, quantum, QCD) with the player
   listing which physics a world uses and in which layer.

### 3.2 Clearly weaker

Each item is [weakens] for any claim that lfphys is a general research tool. These are comparison findings, not an
open-items list; anything to act on belongs in `../../STATUS.md`, section "V. Visualizations — open items".

1. **Depth per domain.** Each domain is a thin slice compared with the specialist: QuTiP (open systems, HEOM), qmsolve
   (2-D/3-D, two particles), KerrGeoPy (inclined, eccentric, plunging Kerr orbits; lfphys is equatorial only),
   GYOTO (ray-traced images, numerical metrics), Meep / Lumerical (full-vector 3-D Maxwell, dispersive media), tmm
   (thick/incoherent layers, ellipsometry, colour), CRunDec (5-loop running, 4-loop decoupling, mass schemes; lfphys
   has 4 loops with 3-loop decoupling), EinsteinPy/SymPy/Mathematica (symbolic GR and QM).
2. **No GPU, float64 only, 1-D/2-D problems.** qmsolve, diffractsim, Qiskit Aer, Lumerical, COMSOL 6.4 and
   OpenRelativity all use GPUs; lfphys's certification is affordable precisely because its problems are small.
3. **Openness and reuse.** No licence, no PyPI package, no public repository, no paper, no external users or
   reviewers. The open analogs declare MIT, BSD, Apache or GPL licences; without a licence nobody can legally reuse
   lfphys.
4. **Validation is internal.** 349 test cases written by the same project (independent agents reviewed them); nothing is cross-checked against an external
   code. Ready external oracles exist: `rundec` (CRunDec) for α_s, KerrGeoPy for Kerr constants and frequencies,
   tmm for multilayers, QuTiP for qubit/Bell states, Astropy for constants.
5. **Visualization and pedagogy.** The player needs a Python server in Docker on a LAN; PhET, Falstad, QuVis and Web
   VPython run in a browser without a server of one's own; QuVis is described as "research-based interactive
   simulations" (St Andrews publication title, found by search [Q14]); PhET's research basis is **not verified**
   here. Parts of the lfphys catalogue text (layer
   descriptions in `registry.py`) are in Russian only.
6. **No real data path for Bell tests.** Qiskit reaches IBM hardware (CHSH tutorial on a 156-qubit device);
   lfphys only simulates.
