# Визуализации следствий гипотез

English version: [README.md](README.md)

Один сервер для всех визуализаций проекта: открывается в браузере с любой машины локальной сети,
визуализации запускаются из браузера по кнопке, каждая — интерактивный плеер.

```
http://<адрес машины в локальной сети>:8479/
```

Правила для визуализаций (физика, причинность, модификации законов, единый API, языки интерфейса) —
[`RULES.md`](RULES.md) (на английском).
Устройство каждой визуализации и её физическая модель — `<id>/README.ru.md` (например, `u32_double_slit/README.ru.md`).
Физика всех визуализаций — в общем движке [`../lfphys/`](../lfphys/README.md): в ядре только проверенная физика,
приближения, интерпретации, модели и альтернативы — отдельными слоями. Визуализация — обёртка над движком; какие его
модули использует текущий мир, плеер показывает в панели «Физика этого мира».

Каждая визуализация относится к одной аудитории; её видно по приставке папки, номер — как в плане: `uNN_` — университет, `rNN_` — исследования, `sNN_` — школа (первая, `s03_projectile`, — с 14.11.2026, остальные в планах), `pNN_` — лаборатории. 13.11.2026 миры переименованы (`v02_double_slit` теперь `u32_double_slit`, `v11_double_slit_2d` — `r12_double_slit_2d`, …); старые имена по-прежнему работают в адресах и в старых запусках (таблица — [`RULES.md`](RULES.md) §8).

Интерфейс говорит по-английски (по умолчанию) и по-русски: переключатель **EN | RU** в верхней строке каждой страницы
сразу меняет язык и запоминается в этом браузере; `?lang=ru` или `?lang=en` в адресе важнее него в этой вкладке, в том
числе на страницах, куда ведут её ссылки. Записи от языка не зависят: запуск, записанный на одном языке, читается и на
другом (в записях, сделанных до перевода интерфейса 12.11.2026, подписи показываются на выбранном языке, а фразы с
числами — так, как были записаны, по-русски).

## Запуск сервера

Из корня репозитория (движок и визуализации):

```bash
docker compose -f visualizations/docker/docker-compose.yml build        # один раз (и после смены requirements.lock)
docker compose -f visualizations/docker/docker-compose.yml up -d viz    # поднять; дальше работает сам и перезапускается
```

Сервер получает только GPU 0 (вторая карта машины разработки считает неверно); тяжёлые части движка уходят на неё там, где это быстрее. Где и с какой точностью считать — страница **⚙ Устройства** (`/settings`): изменения сохраняются сразу и действуют на новые запуски; отдельному запуску можно задать своё устройство и точность прямо на начальной странице (строка «Для этого запуска:» в «Ещё: параметры, затравка, устройство, точность» на карточке демонстрации). В каждом запуске в панели «О запуске» записано, что на чём считалось — отдельно для рисунка и для проверок (проверки всегда в fp64). Если мир сам выбрал приближение (например, срез щели упрощённой 2-D моделью), запуск помечен «приближение» в списке и «ПРИБЛИЖЕНИЕ: …» в верхней строке плеера. На машине без видеокарты NVIDIA: `docker compose -f visualizations/docker/docker-compose.yml --profile cpu up -d viz-cpu`.

Сервер слушает порт **8479** на всех адресах машины. Адрес в локальной сети: `hostname -I` (например `192.168.1.10`).
Порт меняется переменной `VIZ_PORT`. **Входа по паролю нет:** запускать миры может любой, кто достучится до порта; в общей сети ограничьте доступ (например, `VIZ_PORT=127.0.0.1:8479` в `visualizations/docker/.env` — только с этой машины). Остановить: `docker compose -f visualizations/docker/docker-compose.yml stop viz`.

Сервер держит код плеера и визуализаций с диска: правки JS видны после обновления страницы; правки Python
визуализации — в следующем запуске (каждый запуск — новый процесс). Правки самого сервера (`server/lfviz/`) — после
`docker compose -f visualizations/docker/docker-compose.yml restart viz`.

Проверки (все тесты, в Docker):

```bash
docker compose -f visualizations/docker/docker-compose.yml run --rm viz-test
docker run --rm -v "$PWD":/lf:ro -w /lf/visualizations node:24 \
    sh -c 'node --test player/js/tests/*.test.mjs'   # JS плеера: сверка разбора сообщений с байтами Python-кодека, вывод текстов
```

## Как пользоваться

**Начальная страница** (`/`): учебные материалы по физике по аудиториям. Четыре плитки, у каждой — своё число:
**Школа**, **Университет**, **Исследования** и **Лаборатории**. Плитка открывает свою страницу (`/#school`,
`/#university`, `/#research`, `/#labs`; старый адрес `/#playground` ведёт к лабораториям): демонстрации по разделам в
порядке курса, кнопки разделов с числами и поле «Поиск…»; у школы — «Группировать:» по разделам или по классам. Школьные
демонстрации строятся по программе: школьная страница показывает готовые (с 14.11.2026 — «Движение тела, брошенного
горизонтально и под углом к горизонту», s03) и честно — запланированные («Готово: 1 из 45»), а также то, что на ту же
тему уже есть на другом уровне. Запланированные пункты университета и исследований перечислены в свёрнутом
виде, по разделам, под мирами. Под плитками «Продолжить:» показывает последние запуски, открытые или на паузе, у каждого — его состояние («идёт расчёт»
или «пауза»).

В карточке демонстрации: снимок, название, что вы увидите, курсы (университет) или вопрос, «Статус: гипотеза» и
предшественники (исследования). Если у демонстрации есть экраны (см. ниже «Экраны: Наблюдение, Исследование,
Лабораторная работа»), они идут первыми: **«▷ Наблюдение м:сс»**, **«◎ Исследование»**, **«✎ Лабораторная работа»** —
каждая кнопка открывает свою вкладку страницы демонстрации; экран, для которого запись или атлас ещё не сделаны, серый, с
подсказкой «Пока не сделано: соберите локально (site/record.py) или рассчитайте вживую». В школьной карточке есть только
они и, на сервере, «▶ Рассчитать вживую». В карточке университета или исследования дальше — «Сценарий:» (пресеты); **«▶ Рассчитать вживую»** — сервер начинает новый запуск и
открывает плеер; **«▷ Запись м:сс»** — сразу проигрывает сохранённую запись сценария, ничего не вычисляя. Кнопка
доступна, если запись есть на этом сервере или если публичный сайт опубликован и на нём есть запись той же версии мира;
иначе она серая, с подсказкой «Записи пока нет: сделайте её локально (site/record.py) или рассчитайте вживую» (у
сценария, для которого запись вообще не предусмотрена, — «Для этого сценария записи нет: рассчитайте его вживую»; см.
«Записи и публичный сайт» ниже). «Ещё: параметры, затравка, устройство, точность» (в карточке университета свёрнуто, в карточке исследования
открыто) — «Параметры…» (законы и параметры мира вручную), затравка и строка «Для этого запуска:» с устройством и
точностью. «Та же тема:» — ссылки на ту же тему на других уровнях. Если мир с выбранными параметрами создать нельзя,
карточка скажет почему под своими кнопками.

**Мои запуски** (`/runs`, «Мои запуски» в верхней строке): запуски этого сервера — те, где идёт расчёт, на паузе и
приостановленные; «☆» хранить всегда, «✕» удалить (запуск, не открытый ни в одной вкладке; идущий сначала
приостановится). Остановки нет (2026-10-28): запуск либо пишет (считается дальше), либо на паузе. Без зрителей он встаёт
на паузу через минуту, а через полчаса освобождает рабочий процесс («приостановлен»); открыли и нажали ⏺ — мир
продолжается с сохранённого состояния (2026-10-29): рабочий процесс сохраняет полное состояние мира, когда запуск
приостанавливается, когда встаёт на паузу и раз в две минуты счёта, и продолжение идёт с последнего сохранения, как одна
запись, без пересчёта. Если сохранения нет или с тех пор изменился код, который этот мир загружал (файлы движка и
визуализации), или версии Python и библиотек, мир пересчитывается по записи от начала (тот же результат кадр в кадр;
исключение — «призрак» u34, `STATUS.md` V32); каким путём он продолжен, пишет сообщение в событиях. Пока мир
восстанавливается, в строке состояния — «мир восстанавливается — запись продолжится сама»; менять установку в это время
нельзя. Назад по истории плеер идёт от ближайшего ключевого кадра (как в видео: снимок накопленного через каждые 100
сообщений, не больше 256 на мир — дальше реже, равномерно по всей записи), а не от начала записи. От начала записи он
перестраивает вид там, где ключевой кадр не годится: u40 и u41 (облака), u37 после того как старые регистрации вышли за
предел, r12 и r13 до последнего изменения установки. Если продолжение не удалось (например, код визуализации с тех пор
изменился несовместимо), запуск остаётся приостановленным с причиной («продолжение не удалось — ⏺ повторит»), запись
цела. Запуски, к которым не обращались дольше срока хранения (просмотр, команда), удаляются, кроме отмеченных ★; сверх
квоты первыми — те, к которым дольше всего не обращались; открытый во вкладке запуск не удаляется. Срок хранения — поле
над списком на странице «Мои запуски» («Удалять запуски без действий через … дн.», по умолчанию 3 дня); он сохраняется
на сервере (`runs/settings.json`) и действует сразу: если новый срок удалит какие-то запуски, страница сначала покажет
их список и удалит только после подтверждения.

**Плеер** (`/run?id=…`):

| место | что там |
|---|---|
| сверху | название, сцена, плашка **«стандартная физика»** или **«МОДИФИЦИРОВАННАЯ ФИЗИКА: …»**, переключатель миров («Мир 2 (текущий): …», если в запуске их несколько), индикатор «перестраивается установка…» (и «продолжение: мир восстанавливается…»), состояние (идёт расчёт / пауза / приостановлен; вживую / история / конец записи), «☆», **EN \| RU**, тема, справка |
| слева | **Установка — меняется сразу**: всё, что экспериментатор может менять во время опыта (источник, частица, щели, экран, наблюдатель, элементы). Кнопки «применить» нет: изменение действует, как только вы отпустили ползунок, выбрали пункт списка или нажали Enter в поле числа. Невозможное изменение отклоняется, поле возвращается к прежнему значению. **Действия** — разовые события (вспышка, измерение) кнопкой; скорость наблюдателя — ползунком, тоже сразу. **Новый мир: …** — законы и начальные условия (их нельзя менять внутри идущего мира): новый мир начинается в этом же запуске, прежние остаются в записи |
| в центре | сцена визуализации; над ней — быстрые элементы установки (в двухщелевом опыте: наблюдатель, связь детектора, расстояние до экрана, ширина и период щелей) — они меняются сразу, как в панели слева |
| справа | **Проверки: вычислено ↔ эталон**: величина, посчитанная в этом запуске, рядом с эталоном общепринятой физики (✓/✗); сверху — свежие группы, прежние свёрнуты; панели визуализации; **События** (клик — перейти к моменту) |
| снизу | **⏺ запись**: мир считается дальше, кадры добавляются к истории; ещё раз — пауза. **⏮ / ⏭** — в начало / в конец истории, **◀ / ▶** — проиграть историю назад / вперёд с выбранной скоростью. Бегунок в конце истории — запись показывается вживую; в середине — история растёт дальше, а показывается выбранный момент. «\|▶» — кадр вперёд (в конце — шаг расчёта), «⏭ событие» — к следующему событию (за последним — посчитать до него). Скорость — секунд мира за секунду (для расчёта и для проигрывания; шкала логарифмическая, подписана в единицах времени — от долей секунды до лет, в пределах, которые допускает мир; если счёт не успевает, рядом оранжевым — «фактически: …»), «1:1» реальное время, шкала истории текущего мира |

Всё показанное — на момент бегунка: сцена (траектории, экран, облака), окна срезов, проверки, установка, события; при
отмотке назад вид собирается заново из записи до этого момента. Менять установку, совершать действия и двигать срезы
можно только в конце истории.

Клавиши: Пробел — расчёт/пауза, ← / → — проиграть историю назад/вперёд, Home / End — в начало/в конец, N — к событию,
T — тема, ? — справка.

**Слова.** *Запись* («ЗАПИСЬ», «▷ Запись») — сохранённый файл, который проигрывается без расчёта. *Запуск* — живой
расчёт на этом сервере; пока он считает, его состояние — «идёт расчёт» (во вкладке — «… · идёт расчёт»), а то, к чему
⏺ добавляет кадры, — *запись запуска*. Одним словом эти две вещи не называются (`RULES.md` §7, глоссарий).

Если мир долго рассчитывает изменение (сцена, установка, новый мир), вверху видно, что именно и сколько секунд; «✕ отменить»
вернёт мир в момент перед этим изменением. Если мир с выбранными параметрами создать нельзя, начальная страница скажет
почему прямо под кнопкой карточки «▶ Рассчитать вживую», а поле с неподходящим значением подсвечивается. В лаборатории кнопка палитры открывает
параметры объекта; место можно задать числами или щелчком в сцене («⌖ Указать место в сцене»), затем «Поставить».
⇤ и ⇥ вверху (клавиши [ и ]) прячут боковые колонки. Каждому рабочему процессу отведена своя память
(`--worker-mem-gb`, по умолчанию 60 % памяти сервера, не больше 8 ГБ): мир, которому её не хватит, откажет с объяснением,
а не займёт память всего компьютера.

**3D-миры** (сейчас — u38, r11, u39, r12, r13, u40, u41, u42, u43 и u44; правило для всех 3D-визуализаций — `RULES.md` §2.10). В центре — 3D-сцена: установка
(например, заслонка с щелями), падающая волна, посчитанные поля (свет за отверстием, поток энергии) и мишень. Справа —
окна срезов (до трёх), у каждого свой цвет.

| что сделать | как |
|---|---|
| повернуть / сдвинуть / приблизить вид | левая кнопка мыши — повернуть; правая (или Shift + левая) — сдвинуть; колесо — приблизить к точке под курсором; двойной щелчок — сделать точку под курсором центром вращения; F — показать всё нарисованное, Shift+F — всю область; кнопки «Изо», «Сбоку», «Сверху», «С источника», «С мишени» (у плоских миров — «Изо», «Сверху»/«Спереди», «С ребра»). Пока вид не двигали руками, он подстраивается под размер окна и под расширение области; после — остаётся, где его поставили |
| добавить срез | «＋ Срез»: плоскость встаёт в середину области, перпендикулярно уже стоящим (y = c, затем x = c, затем z = c); сразу появляется её окно |
| выбрать срез | щелчок по плоскости в 3D или по её окну; наведение на окно подсвечивает плоскость |
| двигать / наклонять срез руками | у выбранного среза: стрелка двигает его вдоль нормали, два кольца наклоняют (W — двигать, E — наклонять) |
| задать срез числами | панель «Срез: положение и наклон»: центр x, y, z; наклон нормали θ от оси z и азимут φ; кнопки y = c, x = c, z = c, «в центр», «убрать», «по умолчанию» (один срез y = 0) |
| убрать выбранный срез | клавиша Delete (Backspace срез не удаляет) или «убрать» в панели среза |
| автосмещение | галочка «автосмещение по нормали» в той же панели (по умолчанию выключена): срез идёт вдоль нормали, пока идёт время мира (▶); в движении срез грубый, без сверки, полный — когда автосмещение выключено; без галочки срез стоит, где поставлен |
| выключить часть сцены | панель «Слои сцены»: каждая часть отдельно (заслонка, волна, мишень, свет, поток энергии, каждый срез); у света — плотность (оптическая толщина самого плотного луча вдоль оси области, одинаково во всех мирах) и порог; цветовая шкала — в правом нижнем углу 3D |
| окно среза | интенсивность / амплитуда / логарифм / фаза; координаты и значение под курсором; CSV — данные; строка под окном — как посчитан срез и сверка с точным полем |
| снимок | 📷 — PNG 3D-вида |
| камера наблюдателя (u39) | окно справа от 3D: изображение, посчитанное запуском; наведение — доплеровский множитель D, температура, когда излучён свет; PNG — снимок в разрешении расчёта |
| плоскость опыта (r12, r13) | окно справа от 3D: волна \|ψ\|² (интенсивность, амплитуда, логарифм, фаза) с траекториями Бома поверх; при отмотке назад показывает волну того момента; у p02 в плоскости окно волны — главный вид во весь центр, 3D-вид — по кнопке «Показать 3D-вид рядом» (панель «Вид») |
| третье измерение (r12, r13) | вдоль щелей (ось y) установка не меняется, поэтому волна — точное произведение волны на плоскости и свободного гауссова пакета по y (ширина σy — параметр мира «Пакет: ширина вдоль y σy, λ»). В 3D: слой «Волна \|ψ\|² в объёме: ψ(x, z, t)·η(y, t)» (плотность и порог — ползунками слоя), частицы и траектории Бома во всех трёх координатах, на экране — картина P(x, y). Плоскость y = 0 — отдельный слой (выключен) и окно справа |
| наблюдатель у щели (r12) | в форме нового мира «Метка пути в щели B»: «спин частицы: …» (электрон, нейтрон: поле в щели поворачивает спин) или «наблюдатель: детектор пути у щели B (…)» (двухуровневый детектор Энглерта, любая частица); затем слева «Метка в щели B: поворот θ, °» — меняется на ходу: 0 — путь не помечен, 180° — основная поперечная мода щели помечена полностью (полосы почти гаснут; не до нуля — часть волны поворачивается иначе, вероятно высшие моды узкой щели и разброс скоростей). В 3D наблюдатель — оранжевый брусок в щели B, тем плотнее, чем сильнее метка; пресеты «Метка пути: …» и «Наблюдатель у щели B: …» |
| облако и фазы (u40, u41) | облако \|ψ\|² — слой «Облако \|ψ\|² (плотность вероятности)», у него плотность и порог; стрелки — ток вероятности (у вещественных орбиталей их нет). У суперпозиции облако колеблется с периодом Бора: 24 фазы периода открываются, когда до них доходит время мира (панель «Состояние»: какая фаза на рисунке и сколько открыто); при отмотке назад показывается облако того момента; состояние меняется на ходу (слева, «Установка — меняется сразу»): новое n, l, m, суперпозиция или сетка облака — в том же мире, с момента изменения (идеальная подготовка: прежнее состояние отброшено), срезы остаются; период суперпозиции отсчитывается от момента подготовки; другой атом (пара кварков) — новый мир |
| панели атома и кваркония (u40, u41) | «Состояние» — энергия, ⟨r⟩ квадратурой (и по формуле для водорода), вес и фаза каждого состояния суперпозиции; «Радиальное распределение r²\|R(r)\|²» с ⟨r⟩ штрихом; «Уровни энергии» — уровни мира (выделены его состояния, у суперпозиции — ħω); у кваркония пунктиром опыт PDG |
| время прихода (r13) | справа: «Распределение времени прихода» — плотность каждого правила в зависимости от t/t₀ (щелчок по правилу скрывает его; то, что выше рамки, срезано и отмечено ▲), «Место и время прихода» — ток в плоскость j_z(x, t) с попаданиями частиц Бома, «Итоги по правилам» — вероятность прихода за окно, среднее время и разброс по каждому правилу |

Срез считается движком точно для своей плоскости, когда её отпустили; пока плоскость тащат, окно показывает
предпросмотр (помечен). Оси окна — настоящие координаты x, y, z. Срезы сохраняются, когда вы меняете параметры мира
(новый мир в том же запуске). Мир из записи (переключатель миров) только для просмотра: срезы там не меняются; в
прошлом опыта (бегунок не в конце) — тоже: «＋ Срез» неактивна, в панели среза сказано почему.

Записи хранятся в `visualizations/runs/` (срок хранения после последнего обращения — по умолчанию 3 дня, задаётся на странице «Мои запуски» — или до квоты 5 ГБ;
«☆» защищает запуск).
Одновременно считают не больше трёх запусков.

## Записи и публичный сайт

**Как смотреть запись.** Запись — это запуск одного сценария, однажды сделанный записывающей программой и сохранённый:
он сразу проигрывается вперёд и назад, ничего не вычисляя. Откройте её кнопкой «▷ Запись м:сс» в карточке или по адресу
`/run?rec=<мир>/<запись>` (старый id тоже годится: `/run?rec=v02_double_slit/young`). У плеера на записи в верхней
строке плашка «ЗАПИСЬ · дата · код …» (подсказка к ней называет сценарий, а если запись сделана другим кодом, чем у
этого сервера, — оба кода); «⏺», «☆» и «⚙ Устройства» нет. ▶ (или Пробел) проигрывает запись; бегунок, ◀ ▶ и ⏮ ⏭ ходят
по ней, как по истории запуска. Установка, действия и законы показаны «как записаны», менять их нельзя (причина: «это
запись: для этого нужен живой запуск»); 3D-мир показывает записанные срезы и новых не добавляет. Проверки, события,
«Физика этого мира» и графики приборов работают как в запуске; CSV приборов собирается в браузере из кадров, которые
запись сохранила (в столбце времени сказано «из записи: каждый кадр» или «один кадр из k кадров запуска»); перебору
параметра нужен живой запуск. В «О записи» — её паспорт (код, версия записывающей программы, дата, кадры) и «Скачать
запись (.lfrec.gz)». Кнопки скорости в самой картине («▷ полёт» и «▷▷ набор картины» двухщелевого опыта, такие же в u35
и u37) задают скорость плеера; любая другая кнопка, которая изменила бы мир, отвечает «это запись: для этого нужен живой
запуск». Справка (?) описывает запись, заголовок вкладки кончается на «· запись». На сервере «▶ Рассчитать этот
сценарий вживую» начинает запуск того же сценария, который уже можно менять; на публичном сайте заметка слева ведёт к
тому, как запустить lfphys у себя. На телефоне (окно уже 1000 px) плеер в одну колонку: сначала картина, под ней
установка и проверки, внизу экрана — кнопки проигрывания. Адрес с неизвестным миром или записью отвечает «Такой записи
нет» со ссылкой на начальную страницу.

**Где сервер берёт записи.** В `visualizations/recordings/` (её нет в git; переменная `LFVIZ_RECORDINGS` указывает
другую папку), по папке на мир с её `index.json`. Если у мира нет локальной записи, плеер проигрывает запись с
публичного сайта, но только если сайт опубликован (`site/site.json`) и запись сделана той же версией мира. Иначе он
говорит почему: «Записи пока нет: сделайте её локально (site/record.py) или рассчитайте вживую» (сайт не опубликован или
такой записи на нём нет), «Публичный сайт недоступен: …» или, для другой версии, «Для этой версии записи нет: запишите
её локально или рассчитайте вживую».

**Записать локально** (`site/record.py`, в Docker, на процессоре):

```bash
docker run --rm --memory=12g -e LFPHYS_NO_GPU=1 --user "$(id -u):$(id -g)" -v "$PWD":/lf -w /lf/visualizations \
    lfphys-viz python3 site/record.py --stale            # или: --world u32_double_slit (можно несколько), --all
```

`--stale` записывает миры, чьих записей или атласов (экраны «Исследование» и «Лабораторная работа», см. ниже) нет или
которые сделаны другим кодом, и строит атласы после записей: ключ учитывает сценарий, версию записывающей программы и
код, который исполняет запуск (папку мира, `server/lfviz/` без собственных файлов сервера `app.py` и `runs.py`, движок).
Большинство миров записывается от секунд до двух минут, точный двухщелевой опыт r12 — около 20 минут. Каждый файл должен
уложиться в бюджет сайта (желательно 3 МБ, не больше 10 МБ; мир вместе с атласами — 12 МБ, не больше 25 МБ); запись сверх предела не получится, с советом укоротить её в `VIZ["recordings"]` мира. Снимки для карточек и README
(`docs/images/<id>.jpg`) делает из записей `site/posters.mjs`.

**Собрать публичный сайт локально** (`site/build.py`, затем `site/check.py`, который падает, если что-то пропущено,
устарело или не укладывается в бюджет):

```bash
python3 site/build.py --recordings recordings --out /tmp/site --base /lfphys/
python3 site/check.py /tmp/site --base /lfphys/
cd /tmp && mkdir -p srv && ln -s /tmp/site srv/lfphys && cd srv && python3 -m http.server 8000   # http://127.0.0.1:8000/lfphys/
```

Сайт — тот же плеер в статическом режиме: начальная страница и записи, без вычислений; лаборатории серые, с пометкой
«Работает только с запущенным сервером»; ссылок «Мои запуски» и «⚙ Устройства» там нет. Подробности:
[`site/README.md`](site/README.md) (на английском).

**Публикация.** Сайт публикуется на GitHub Pages (`https://ildar-idrisov.github.io/lfphys/`) процессом
`.github/workflows/pages.yml` (работает с 2026-11-14). Push в `main` проверяет, записывает и собирает; публикует сайт
только ручной запуск процесса автором (Actions → pages → Run workflow) с `deploy: true`.

## Экраны: Наблюдение, Исследование, Лабораторная работа

С 14.11.2026 у школьной или университетской демонстрации может быть три экрана — вкладки одной страницы
(`/run?demo=<мир>&screen=watch|explore|lab` на сервере, `run.html?demo=…` на публичном сайте): **Наблюдение**,
**Исследование** и **Лабораторная работа**. Они работают и на публичном сайте: всё, что они показывают, движок рассчитал
заранее — записи и **атласы** (собственные запуски мира во всех точках сетки управляющих элементов). Первые —
`s03_projectile` (все три экрана) и `u32_double_slit` (Наблюдение и Исследование); остальные демонстрации пока
открываются в полном плеере и получат экраны по очереди. Вкладка входит в адрес, так что ссылка открывает тот же экран;
при переключении вкладок каждый экран сохраняет своё состояние. **«Почему этому можно верить»** в верхней строке (на
телефоне — под ☰) открывает одну панель: проверки показанного по общепринятым формулам, «Физика этого мира», события и
паспорт (откуда данные: ключ атласа, код, затравка, точка). На телефоне (390 px) страница идёт одной колонкой: картинка,
управляющие элементы, строка времени внизу.

* **Наблюдение** — запись настоящего запуска с подписями: на что смотреть, шаг за шагом. Подпись под картинкой меняется
  по ходу времени; каждая подпись — засечка на шкале времени (щелчок переводит туда), ◀◀ / ▶▶ — к предыдущей или
  следующей подписи. Подпись может на несколько секунд задержать воспроизведение, чтобы её успели прочитать. Другие
  записи u32 — в списке «Другие записи».
* **Исследование** — ползунки и переключатели сбоку останавливаются только на рассчитанных точках: каждое положение — это
  запуск, который движок посчитал; между ними ничего не дорисовывается. «▶ Запуск» (s03) бросает выбранную точку с
  t = 0; изменение управляющего элемента готовит следующий запуск, а прежние остаются бледными следами со своими
  значениями («Убрать следы» стирает их). В u32 изменение действует сразу и сохраняет число попаданий, так что две
  постановки сравниваются при равном счёте. «Показать» включает и выключает то, что рисуется (траектория, точки через
  0,1 с, скорость, силы, энергия; в u32 — кривая ожидания, кривая без интерференции, волна, линии тока). Показания (s03:
  дальность, время полёта, наибольшая высота) стоят «—», пока время запуска не дошло до события, которое их определяет.
  Сочетание, которое мир отвергает (s03: с пола под углом 0°), объясняет почему, и ▶ недоступна. На сервере
  **«▶ Рассчитать вживую»** в верхней строке открывает полный плеер с той же постановкой, ползунки двигаются и между
  рассчитанными точками, а значение между ними рассчитывается на сервере, когда ползунок отпущен (в паспорте и у следа —
  пометка «расчёт вживую»); в u32 «Другая выборка» даёт другой набор попаданий с той же статистикой.
* **Лабораторная работа** (s03) — опыт по частям («Часть 1 из 3: …»): у каждой части своя цель, постановка и приборы
  поверх картинки (рулетка на полу, линейка, транспортир у пусковой установки, секундомер). Запустите, затем
  «Измерить»: каждый прибор части снимает показание в показанный момент, округлённое до цены деления и с погрешностью;
  строка попадает в таблицу (строку можно удалить, «Очистить таблицу» очищает всё, таблица скачивается в CSV с
  погрешностями). На графике — точки с погрешностями и проведённая прямая; подгонка даёт свой параметр с погрешностью.
  **«Сверить с законом»** сравнивает его с законом, который рассчитал мир (✓ в пределах двух погрешностей или ✗ с
  подсказкой). Секундомер нажимают рукой, он измеряет вашу собственную реакцию (около 0,1 с), поэтому медленная скорость
  для него недоступна. Таблица хранится в этом браузере.
* **Рабочий лист** — «Рабочий лист (печать) →» в карточке работы (`/worksheet?demo=s03_projectile`, на сайте
  `worksheet.html?demo=…`): название работы по ФРП, цель, части с приборами, пустая таблица и оси графика, оборудование и
  вопросы, по одной странице A4 на часть («🖨 Печать»). «Для учителя» добавляет ответы, заметки для учителя и значения
  законов на отдельных страницах. На каждой напечатанной странице есть строка с указанием авторства материалов (они
  распространяются по CC BY-NC-SA 4.0).

**Атласы локально.** `site/record.py` строит атласы мира сразу после его записей (команда — в «Записать локально» выше;
s03 и u32 — около минуты каждый) в `visualizations/recordings/<мир>/atlas/`; `site/atlas.py --world <id>` строит только
атласы. Экран без атласа говорит «Пока не сделано». Подробности для разработчиков (на английском): [`RULES.md`](RULES.md)
§10.

## Лаборатории (B6, 2026-11-03)

Плитка **«Лаборатории»** на начальной странице (`/#labs`) открывает по лаборатории на раздел физики, `pNN_*`, где сцена
собирается руками и всё рассчитывается в реальном времени (запрос автора 2026-10-28); демонстрации `sNN_`/`uNN_`/`rNN_*`
выше — подготовленные опыты. Лабораториям нужен запущенный сервер: проигрывать в них нечего, поэтому на публичном сайте
они серые, с пометкой «Работает только с запущенным сервером». В карточке раздела: сценарий (готовая сцена), «▶ Начать»,
«Законы…» (законы мира: какой решатель, пространство, сетка — их смена начинает новый мир) и «📂 Из файла сцены…».

В плеере лаборатории слева:

* **Палитра: добавить в сцену** — добавить объект в текущий момент мира: перед установкой открывается форма его параметров, точку можно указать щелчком в сцене; мир сдвигает объект на свободное место или объясняет, почему поставить нельзя, а недоступные кнопки показывают причину;
* **Объекты сцены** — выбрать, ⧉ копия, ✕ удалить (тоже в текущий момент);
* **Перетаскивание и бросок** — объект выбирается щелчком в сцене или в окне среза (кольцо с именем, инспектор
  показывает его), перетаскивается мышью: перетаскивание двигает «призрак» (в 3D — в плоскости через объект поперёк
  взгляда, в плоском мире и в окне — в их плоскости, поршень и стенки — вдоль своей оси), изменение применяется при
  отпускании, в текущий момент мира. Shift + перетащить — бросок: скорость — как двигалась рука за последнюю 0,1 с при
  текущей скорости воспроизведения, умноженная на масштаб броска (поле «Бросок (Shift): масштаб ×» в панели «Объекты сцены»);
  скорость видна у курсора.
  Масштаб броска «авто» подобран по самому миру: быстрый взмах (ширина вида за секунду) бросает объект через всю
  область мира примерно за 2 секунды при текущей скорости воспроизведения, но не быстрее половины наибольшей скорости,
  которую мир объявил. Если бросок ограничен этой скоростью или мир его не принял, плеер так и пишет: «уменьшите
  масштаб броска». Если мир не может так поставить объект, он объясняет почему, а призрак возвращается; в прошлом записи
  и пока мир считает, двигать нельзя. Delete удаляет выбранный объект, в том числе выбранный в окне плоского мира; Esc
  отменяет перетаскивание;
* **Новый мир с переносом сцены** — в форме «Новый мир: …» видны все законы нового мира, в том числе меняющиеся на ходу
  (сетка, окно, края — с их текущими значениями). С галочкой «перенести сцену» (включена) объекты переходят в новый мир
  с теми же номерами, время продолжается. Сообщение после переноса говорит по каждому объекту: перенесён с состоянием,
  по параметрам (своего состояния у него нет), состояние не перенесено и начато заново из параметров (с причиной),
  что изменено при переносе, что новый мир не принял — и что стало с состоянием самого мира (например, течение
  перенесено или начато заново из покоя);
* **Инспектор** — параметры выбранного объекта, меняются сразу; под ними «сейчас:» — его посчитанное состояние;
* **Сцена: файл** — сохранить сцену в файл и начать из файла новый мир;
* **Запись: окно** — запись держит последние 10 минут счёта (пауза и приостановка не в счёт) или 1 ГБ. Увидели
  эффект — «● Сохранять запись»: окно и всё дальнейшее сохраняются. Продолжить приостановленный мир можно с
  контрольной точки внутри окна (раз в минуту счёта и на паузе); если начало мира уже вышло из окна (или в
  сохранённой записи дыра — запись включали и выключали), пересчитать мир с начала нечем — так и пишется.

Справа — проверки законов сохранения вживую, **Датчики** (детекторы, часы, датчики поля) и **Изменения сцены** (щелчок —
к этому моменту). Сообщения и отказы появляются справа внизу стопкой, новое сверху; каждое держится, пока на нём курсор,
и закрывается щелчком.

**Приборы и перебор параметра.** Если мир сообщает измеряемые величины, справа появляется панель «Приборы»: величины по
группам и значение каждой на момент бегунка. Отметьте величину — появится её график по записи (у каждой свой): до
бегунка ярко, после — бледно (будущее записи), черта — бегунок; наведите указатель, чтобы прочитать значение.
Свёрнутые группы и выбор величин запоминаются для этого запуска. «⤓ CSV» — отмеченные величины из записи, все кадры,
полная точность («только до бегунка» обрезает); в первой строке — единица времени и подписи с единицами.

«Перебор параметра»: тот же опыт от текущего момента мира повторяется для каждого значения закона (из «Законы мира —
меняются сразу») или параметра объекта, и для каждого измеряется величина — в конце, среднее за последние N, максимум
или минимум. Под «Что менять» написано, что задано сейчас; для положения объекта — ещё и где он сейчас. Каждое
значение, в том числе равное заданному, применяется заново: положение и скорость — как перетаскивание и бросок в момент
перебора. Значения — через «;» или пробел (десятичная точка или запятая), или рядом «от … до …». Время счёта — в единицах
масштаба мира (например, фс), по умолчанию — пять секунд мира при выбранной скорости; рядом с «Число замеров» видно, через
сколько времени мира берутся замеры. Сначала «Оценить» (сколько займёт счёта; предел 10 мин), потом «▶ Запустить
перебор»; после запуска оценку нужно сделать заново.

Перебор рассчитывается в отдельном процессе и идущий мир не меняет: у перебора своя, меньшая доля памяти, и если памяти не хватит,
система первым остановит перебор, а не мир. Перебор сам остановится, если превысит предел. «✕ отменить» останавливает
его, рассчитанное остаётся; «убрать» удаляет законченный перебор с результатами. Результат — таблица, график и «⤓ CSV
таблицы» (в первых строках CSV — с какого момента, сколько и как часто мерили); отказ мира — в таблице с причиной, а
если не измерено ни одно значение, перебор помечен «не рассчитан». Тот же перебор от того же состояния даёт те же числа; у

Опишите, что нужно увидеть и какая гипотеза или эффект проверяется. Агент создаёт подпапку `uNN_<название>/` (или `sNN_`, `rNN_`: аудитория и номер в плане) по

`../reviews/`; демонстрация ещё объявляет свои записи (`VIZ["recordings"]`), их записывает `site/record.py`, а снимок
делает `site/posters.mjs`. Сервер, плеер, начальная страница и каталог корневого README (`site/readme.py`) подхватывают
папку сами.

## Если что-то не так

| симптом | причина |
|---|---|
| страница не открывается с ноутбука | сервер не поднят (`docker ps` → `lf-viz`) или порт закрыт сетевым экраном |
| «заняты все рабочие процессы (3): …» | три запуска открыты в браузере: закройте вкладку одного (он встанет на паузу и освободит рабочий процесс; продолжится по ⏺). Запуски без зрителей освобождают рабочие процессы сами |
| «эта запись сделана до версии, умеющей продолжать запуски: …» | запуск создан до 2026-10-28: его можно смотреть, но не продолжить — начните новый мир или новый запуск |
| запуск сразу «сбой» | законы несовместимы (например, ОТО с эфиром) — причина в «События» и в `runs/<id>/worker.log` |
| «продолжение не удалось — ⏺ повторит» | мир не удалось пересчитать по записи (причина — в подсказке строки состояния и в «События»); запись цела, ⏺ пробует снова, когда причина устранена |
| «мир ещё восстанавливается: изменение не принято — …» | изменение пришло, пока мир восстанавливается по записи (например, из другой вкладки); повторите его, когда запись продолжится |
| у запуска на странице «Мои запуски» нет «✕» | он открыт во вкладке (👁 в списке): закройте её |
| мир идёт медленнее выбранной скорости | вычисление не успевает: рядом со скоростью оранжевым «фактически: …» (до 2026-10-28 плеер этого не показывал, хотя здесь было написано обратное); уменьшите скорость или темп источника |
| правка сервера не видна (в том числе «ImportError» у новой визуализации: сервер держит движок, загруженный при старте) | `docker compose -f visualizations/docker/docker-compose.yml restart viz` — запуски не теряются: идущие приостановятся и продолжатся по ⏺ |
